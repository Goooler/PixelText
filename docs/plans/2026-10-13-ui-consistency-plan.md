# 规则管理与备份恢复页面一致性修改方案

## 目标与边界

统一骚扰识别白名单、关键词拦截、备份恢复的视觉层级与组件。设计由 Gemini 3.8 Flash High 根据现有实屏及源码提出，实施由 GPT-6.1-sol high（fast）完成，代码及最终结果由 GPT-6-astra high（fast）审查，Gemini 复审实屏 UI。

保留 Compose、Material Expressive 主题、Dynamic Color、暗色及现有必要动效；不新增依赖、权限、网络请求或备份格式，不修改仓库、数据库和业务规则。用户已有依赖更新独立保留。本次不提交 Git、不新增或运行单元测试。

此前保留的初始化覆盖人工分类、等效迁移结构备份被拒、录音触发模拟器失去响应三个问题继续待处理；外部短信入口系统栏、资源更新错误英文文案也不混入本次修改。

## UI 设计

### 白名单与关键词拦截

- 规则提示与条目使用现有 20dp 圆角，页面水平 16dp、条目间隔 12dp，底部避让扩展 FAB 与导航栏。
- 提示卡内边距 16dp，图标与文字形成层级，使用 secondaryContainer / onSecondaryContainer；规则条目使用 surfaceContainer，内边距沿用关键词的起始 18dp、上下 14dp、末尾 6dp。
- 标题 titleSmall/titleMedium，正文 bodyMedium，辅助 bodySmall，计数 labelLarge；相同角色采用一致字体与颜色。
- 空态保留语义图标，统一 48dp 图标、titleMedium 标题和居中 bodyMedium 说明。复用小型规则空态，不强制其他页面更换插画。
- 白名单增加规则计数；删除图标及确认按钮使用 error，编辑操作沿用正常颜色。
- 白名单说明保留完整语义：新旧命中消息非骚扰、不执行骚扰静默/隔离/自动操作、规则仅本机保存、删除不撤销已有放行且不恢复已删除消息。Gemini 短文案不足以承载全部语义，因此保留补充说明。
- 保留精确号码/正则、批量号码、试匹配、历史放行确认、进度及错误；不要求复杂白名单编辑器与关键词单字段编辑器同尺寸。保留关键词重建和保存流程。

### 备份与恢复

- 分开“备份内容”“导出与安全”“从文件恢复”，任务容器 24dp 圆角、内边距 16dp、分组间隔 16dp。预览和结果使用 28dp 圆角，避免无意义的多层嵌套。
- 保留顶部备份范围说明及权限/default SMS 入口；不暗示支持彩信备份。
- 加密导出使用左侧标题/说明、右侧 Switch；密码短标签“密码”，确认标签“确认密码”，详细用途与安全说明使用辅助文字。共享密码仍能用于加密导出与恢复，禁止持久化密码。
- 创建备份属于导出区域，选择文件属于恢复区域。明确表达恢复所需密码的入口，保持所有原有按钮启用条件、文件选择、默认加密与未加密确认。
- 预览使用可换行的时间/短信数量摘要，保留设置覆盖、去重、规则并集、SIM、出站消息与归档影响说明。恢复选择内容、开始恢复及关闭预览可达。
- 恢复保护使用 primaryContainer / onPrimaryContainer，完整保留取消不撤销写入及验证码清理说明；真正失败使用 errorContainer / onErrorContainer。
- 合并文件错误不得统一设置密码字段 isError；操作错误应明显且靠近相关区域，无法从现有状态可靠区分导出/恢复时采用通用操作反馈，不能虚构错误归因。确认密码不一致等明确字段校验可以内联，保留原启用规则。
- 结果卡保留新增、已存在、失败、未处理、出站转失败、关联跳过和完成分组全部信息；长文本、计数和按钮允许换行，结束保护与重选文件流程保持。
- 保留各忙碌阶段文案、进度指示及停止后续处理按钮，不给未测量过程编造预计耗时。
